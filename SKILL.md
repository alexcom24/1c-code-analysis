# 1C Code Analysis

Разбор **выгрузки** на скорость и оптимальность. Результат — **один офлайн-HTML** с двумя слоями сразу:

1. **Разбор по кускам** — карточки проблем: где в коде, что ломает человеческим языком, цитата стандарта ИТС.
2. **Цельная вставка** — самодостаточный блок: один Select All → Copy → в конфигураторе заменить указанный фрагмент один раз.

Перед работой прочитай [protocol.md](protocol.md) и [html-report.md](html-report.md).

## Главное правило результата

Пользователь **не должен** думать, куда вставить текст запроса, что ещё поменять в обходе / параметрах / вызовах и в каком порядке склеивать куски.

Ты отдаёшь **самодостаточный блок**: внутри уже и запрос, и BSL вокруг него, и связанные процедуры, если без них вставка сломается.

**Запрещено** как основной ответ (и в чате, и в HTML):

- «замени только текст запроса» / «добавь эти 5 строк в цикл»;
- несколько пакетов, которые пользователь должен сам склеить;
- дифф по строкам;
- таблица «находка | #std657 | вставка 1» **без** карточек с цитатами ИТС;
- только советы и фрагменты «замени этот пакет» **без** цельной вставки в конце.

Оба слоя обязательны. Старые отчёты с карточками, но без цельного кода — недостаточны. Новые отчёты со вставкой, но без карточек и цитат — тоже недостаточны.

## Когда применять

- аудит выгрузки / расширения / модуля / проведения / СКД;
- «дай готовое, чтобы вставить одним куском».

## Стек

| Слой | Роль |
|------|------|
| XML-выгрузка | имена объектов и полей |
| MCP BSL LS `analyze_file` | диагностики `.bsl` |
| MCP v8std | формулировки стандартов: `v8std_get_page` для цитат; без `v8std_explain_snippet` для закрытого кода |
| `composing-1c-queries`, `1c-query-optimization` | запросы |
| `1c-bsp-api` | вызовы БСП: имя модуля/метода и сигнатура до вставки |
| `anti_patterns`, `query-optimization-tips`, `1c-coding-standards` | рамки |

## Оси

- **A** — стандарт / антипаттерн.
- **B** — риск прода и учёта (блокирует выпуск).

По умолчанию критерий — скорость и оптимальность.

## Режимы

| Режим | Когда |
|-------|--------|
| **A** | один объект / метод |
| **B** | расширение целиком (карта → топ узлов) |
| **C** | кусок типовой — только с явной границей |
| **D** | только метки / префикс |

## Порядок

1. Путь выгрузки + граница режима.
2. Карта горячих узлов.
3. Разбор → оси A/B. Цитаты ИТС брать из `v8std_get_page`, не выдумывать.
4. Собрать **вставки** по protocol.md (крупные самодостаточные блоки).
5. Один HTML по [html-report.md](html-report.md): карточки + вставки. В чат — путь, статус, ИКО, сколько вставок.
6. В файлы выгрузки не писать, пока не сказали «внеси».

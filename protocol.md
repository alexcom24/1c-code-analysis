# Protocol: разбор выгрузки 1С

## 0. Вход

1. Путь к выгрузке (`*.bsl`, `*.xml`).
2. Что анализируем (расширение / конфигурация / EPF).
3. Для расширений — выгрузка основной конфигурации того же релиза, если есть.
4. Критерий по умолчанию — скорость и оптимальность.

Нет пути — спросить. Имена объектов не выдумывать.

## 1. Режим

| Запрос | Режим |
|--------|--------|
| один объект / проведение / модуль | **A** |
| «проверь расширение» | **B** |
| подсистема / кусок типовой | **C** (нужна граница) |
| только префикс / метки | **D** |

## 2. Карта

В границе: модули, `Новый Запрос`, виртуальные таблицы, циклы с запросами, СКД, точки входа (проведение, обмен, печать).

## 3. Разбор узла

Читай **всю** процедуру (или весь модуль/область, если процедуры связаны), не три строки вокруг бага.

Дальше: `analyze_file` → rules/skills запросов → v8std по коду → оси A/B → сразу проектируй **вставку** (§5).

---

## 4. ИКО в чат

- **И** — граница и режим  
- **К** — 1–5 главных находок (ось A/B)  
- **О** — стоп / можно с оговорками / можно в прод  

+ путь к HTML + число **вставок**.

Если вставок 1–2 — продублируй их код в чат целиком. Если больше — в чате оглавление, код только в HTML.

## 5. Вставка — как для человека, который не хочет думать

### 5.1. Смысл

Вставка = **один** блок текста, который пользователь:

1. копирует целиком;
2. в указанном месте конфигуратора **целиком заменяет** старый фрагмент;
3. больше ничего не подклеивает.

Все зависимости уже **внутри** этого блока (запрос, параметры, обход, вспомогательные процедуры, которые иначе нужно менять синхронно).

### 5.2. Что брать границей блока (от мелкого к крупному — бери достаточное)

Выбери **минимальный уровень, на котором вставка самодостаточна**:

1. **Одна процедура/функция** — если запрос, параметры и обход живут только в ней.  
   → В блоке: от шапки-комментария и `Процедура`/`Функция` до `КонецПроцедуры`/`КонецФункции`.  
   → Пользователь: найти метод → выделить метод целиком → вставить.

2. **Несколько процедур подряд одним блоком** — если меняются вместе (общая `ВыполнитьЗапрос*` + проведение, или клиент+сервер одной команды).  
   → В блоке: все эти процедуры **подряд**, в порядке, удобном для замены (сначала серверные/общие, потом вызывающие — как в модуле).  
   → В инструкции: «выделить с процедуры `А` по процедуру `Б` включительно → заменить этим блоком».

3. **Целая область модуля** (`#Область ... #КонецОбласти`) — если правок много внутри области и нарезать опасно.

4. **Весь модуль** (`Module.bsl`) — если модуль небольшой или связанные правки размазаны по файлу так, что точечная замена процедур рискованна.  
   → Инструкция: «открыть модуль → Ctrl+A → вставить».

5. **СКД** — не «только строка запроса», а **полный текст запроса набора данных** + если меняются поля/ресурсы из‑за новых алиасов — **в том же блоке инструкции** явный список «после вставки запроса проверь поля» **либо** (предпочтительно) полный комплект: текст запроса + таблица «поле набора → выражение», чтобы не гадать.  
   Если из BSL вызывается отчёт и ломается программная настройка — BSL-процедуру настройки отдать **тем же номером вставки** вторым блоком только если иначе нельзя; лучше связать: «Вставка 2 зависит от Вставки 1» и в HTML держать рядом. Идеал для СКД+код: одна вставка = «модуль, который заполняет СКД» целиком, а текст набора — если он в схеме, отдельной вставкой **с полной схемой шагов без размышлений**.

**Никогда** не отдавай отдельно:

- голый `ВЫБРАТЬ ...` «вставь в Запрос.Текст»;
- кусок `ГДЕ` / один `ПОМЕСТИТЬ`;
- «добавь параметр `&Склад`» без полной процедуры, где параметры устанавливаются.

Запрос всегда уже **вшит** в BSL-единицу (п.1–4), либо для чистой СКД — полный текст набора целиком как единственное содержимое вставки с заголовком «заменить весь запрос набора `ИмяНабора`».

### 5.3. Карточка вставки (обязательно)

```
Вставка N. <краткий заголовок>
Куда: <путь файла выгрузки> → <объект метаданных> → <модуль>
Что выделить: <имя процедуры / с процедуры А по Б / весь модуль / набор СКД …>
Действие: удалить выделенное → вставить этот блок (один раз)
Зачем: <ось A/B, одна фраза>
Проверка после: <одна фраза: провести документ / открыть отчёт / …>

<один code fence — полный текст>
```

Без дыр `// ...` посередине. Без «и ещё не забудь».

### 5.4. Несколько вставок

Допустимы, только если это **разные объекты/модули** (например общий модуль + модуль документа).

Тогда:

- жёсткий порядок: «Сначала Вставка 1, потом Вставка 2»;
- у каждой — своё «куда» без двусмысленности;
- пользователь по-прежнему **не склеивает** код вручную внутри модуля.

Если два изменения в **одном** модуле — это **одна** вставка (больший блок), а не две.

### 5.5. Запрещено

- точечные правки и мини-диффы;
- «замени запрос, цикл оставь как был», если цикл тоже надо менять;
- пакеты, от которых пользователь должен сам протащить зависимости;
- выдуманные имена метаданных;
- псевдокод.

### 5.6. Качество

- запросы по `composing-1c-queries` / `1c-query-optimization`, `|` в тексте;
- стиль — coding standards;
- для оси B в карточке — обязательная проверка на копии ИБ.

## 6. HTML-отчёт (один файл)

1. Паспорт (что, где, режим, дата).  
2. Итог + статус + число вставок.  
3. Оглавление вставок (N, куда, что выделить).  
4. Ось B, ось A (со ссылкой на номер вставки).  
5. Карта границы.  
6. **Вставки** — полный текст карточек §5.3 (главный раздел).  
7. Напоминание: в выгрузку агент сам не пишет, пока не попросили.

Офлайн-HTML, без CDN.

---

## 7. Не делать

- аудит всей типовой без границы (C);
- MCP живой ИБ для этого протокола;
- закрытый код в `v8std_explain_snippet`;
- закончить отчёт советами без вставок, если код можно написать по выгрузке;
- если не хватает текста модуля/СКД — один раз спросить, не выдумывать.

## 8. Skills рядом

- запросы — `composing-1c-queries`, `1c-query-optimization`;
- после «внеси в выгрузку» — `analyze_file`.

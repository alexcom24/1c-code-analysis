# HTML-отчёт: разбор + цельная вставка

Два слоя в **одном** офлайн-HTML. Не выбирай один из них.

| Слой | Откуда взято | Зачем |
|------|----------------|-------|
| Разбор по кускам | отчёты вроде `Анализ_XCOM_ВыручкаРСК74.html` / `Анализ_alsn_расширение_XCOM.html` | человек читает *конкретный* кусок кода, *зачем* это плохо, *цитату стандарта своими словами ИТС* |
| Цельная вставка | текущий шаблон (кнопка «Копировать») | один Select All → в конфигуратор, без склейки пакетов |

**Запрещено отдавать HTML, в котором есть только таблица «находка / #std657 / вставка 1» без карточек с цитатами.** Такая таблица может быть *оглавлением* к карточкам, не заменой.

**Запрещено отдавать только советы и куски запросов** («замени этот пакет») как основной ответ. Кусок в карточке — иллюстрация «как есть». Рабочий код — только во вставке целиком.

## Порядок секций

1. Шапка (объект, путь, релиз, режим, дата, критерий).
2. Содержание с якорями.
3. Методика ИКО (шкала 0–10, шаг 0,5; четыре критерия и веса; бейджи серьёзности).
4. Итог: балл **было → станет**, расчёт по весам, статус выпуска (стоп / можно с оговорками / можно в прод).
5. Как устроен объект: точка входа, ветки, что уже сделано удачно.
6. Диагностики BSL LS / АПК: таблица код → суть → где в тексте → стандарт ИТС.
7. **Проблемные места** — карточки `.issue` (главный читаемый раздел).
8. Вставки — карточки protocol.md §5.3, полный текст, кнопки копирования.
9. Футер: в выгрузку агент не писал, пока не сказали «внеси».

Офлайн, без CDN. Палитра и карточки — как в августовских отчётах (бейджи, `.quote`, `.issue`, содержание). Кнопки копирования и `.ins` — как в шаблоне со вставками.

## Карточка проблемного места

Обязательные поля:

- бейдж: Критично / Высокий / Средний / Низкий;
- заголовок с номером (`5.1. …`);
- **где:** объект, модуль/набор СКД, имя пакета или процедуры, поле/конструкция;
- **что происходит** — 1–3 абзаца человеческим языком (не «нарушен std654», а что СУБД/учёт сделает на базе УТ);
- **цитата стандарта** в `.quote` с `<cite>`: текст взять из MCP `v8std_get_page` (страница стандарта), не выдумывать и не сжимать до одного хеша `#std657`;
- коды диагностик, если есть (`bslls:…`, `АПК:…`);
- **вставка:** номер вставки, которая это закрывает, **или** явно «оставлено» и почему (бизнес-правило, ось B, нужна проверка человеком).

В карточке можно показать *короткий* фрагмент «как есть» (`pre`). Это не замена вставки.

Скелет:

```html
<article class="issue crit">
  <h4><span class="badge b-crit">Критично</span> 5.1. Заголовок</h4>
  <p class="path">Объект / набор СКД / пакет <code>втИмя</code> / поле</p>
  <p>Что происходит на базе УТ — человеческим языком.</p>
  <div class="quote">
    Текст стандарта из v8std_get_page, не пересказ одним хешем.
    <cite>Название стандарта. ИТС. #stdNNN</cite>
  </div>
  <p><b>Диагностика:</b> <code>bslls:…</code> / <code>АПК:…</code></p>
  <p><b>Вставка:</b> закрыто вставкой 1 / оставлено: …</p>
</article>
```

Цитаты: по одному стандарту на блок `.quote`. Несколько стандартов — несколько цитат. Закрытый код клиента в `v8std_explain_snippet` не отправлять; для формулировок — `v8std_get_page` / поиск по id.

## ИКО

Собственная шкала, не балл АПК и не MethodSize BSL LS.

Веса при критерии «скорость и оптимальность»:

| Критерий | Вес |
|----------|-----|
| Производительность | 35% |
| Корректность расчета / учёта по тексту | 30% |
| Стандарты ИТС | 20% |
| Сопровождаемость | 15% |

Покажи четыре оценки 0–10 и итоговую формулу. Если есть вставка — два итога: исходник и после вставки.

Серьёзность: критично ломает скорость или цифры на типичных данных; высокий — прямое нарушение ИТС по запросам; средний — лишняя работа СУБД / путаница СКД; низкий — стиль и имена.

## Вставки в том же файле

После карточек — секция «Вставки». Правила protocol.md §5 без изменений: самодостаточный блок, один раз вставить, без диффа.

Кнопка копирует `textContent` из `<pre id="…">` (в HTML-источнике параметры запроса экранировать как `&amp;`).

## Чат

ИКО коротко + путь к HTML + число вставок. Полные цитаты и карточки — в HTML, не дублируй все карточки в чат. Код вставки в чат целиком только если вставок 1–2 и пользователь явно просит вставить в чат; иначе код только в HTML (длинный запрос СКД).

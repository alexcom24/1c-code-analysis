# 1C Code Analysis

Разбор **выгрузки** на скорость и оптимальность + **готовая вставка одним копированием**.

Перед работой прочитай [protocol.md](protocol.md).

## Главное правило результата

Пользователь **не должен** думать:

- куда вставить текст запроса;
- что ещё поменять в обходе выборки / параметрах / вызовах;
- в каком порядке применять куски.

Ты отдаёшь **самодостаточный блок**: внутри уже и запрос, и BSL вокруг него, и связанные процедуры, если без них вставка сломается. Один Select All в блоке → Copy → в конфигураторе заменить указанный фрагмент → Paste **один раз**.

**Запрещено** как основной ответ:

- «замени только текст запроса»;
- «добавь эти 5 строк в цикл»;
- несколько пакетов, которые пользователь должен сам склеить;
- дифф по строкам.

## Когда применять

- аудит выгрузки / расширения / модуля / проведения / СКД;
- «дай готовое, чтобы вставить одним куском».

## Стек

| Слой | Роль |
|------|------|
| XML-выгрузка | имена объектов и полей |
| MCP BSL LS `analyze_file` | диагностики `.bsl` |
| MCP v8std | формулировки стандартов (без `v8std_explain_snippet` для закрытого кода) |
| `composing-1c-queries`, `1c-query-optimization` | запросы |
| `1c-bsp-api` | вызовы БСП: имя модуля/метода и сигнатура до вставки |
| `anti_patterns`, `query-optimization-tips`, `1c-coding-standards` | рамки |

## Оси

- **A** — стандарт / антипаттерн.
- **B** — риск прода и учёта (блокирует выпуск).

По умолчанию критерий — скорость и оптимальность.

## Режимы

| Режим | Когда |
|-------|--------|
| **A** | один объект / метод |
| **B** | расширение целиком (карта → топ узлов) |
| **C** | кусок типовой — только с явной границей |
| **D** | только метки / префикс |

## Порядок

1. Путь выгрузки + граница режима.
2. Карта горячих узлов.
3. Разбор → оси A/B.
4. Собрать **вставки** по protocol.md (крупные самодостаточные блоки).
5. Один HTML-отчёт; в чат — путь, статус, ИКО, сколько вставок.
6. В файлы выгрузки не писать, пока не сказали «внеси».
